# Known limitations

- Separate detailed approved master-plan text not available at bootstrap; later stage names and gates are provisional.
- Public repository: do not store confidential competitive research or unauthorized materials. Do not change visibility or spending settings without explicit authorization.
- No verified rights to use/distribute game-specific card data or conduct restricted automated gameplay; no such data or activity in bootstrap.
- No project distribution license selected. Toolchain inventory is not a complete transitive license audit.
- Synthetic probe validates only compilation and subprocess contract; it is not a game engine, agent or benchmark.
- Linux x86-64 tested only; Windows, macOS, MSVC and cross-platform reproducibility not yet validated. CTR-0.2 Clang ASan/UBSan passed; this is not exhaustive memory-safety proof.
- No official rules version, formats, functional identity catalog, card coverage, game-specific replay, agents, deck optimizer, match/tournament logic or simulation samples exist.
- No CI workflow or local PC execution configured; GitHub quota/spend settings not verified. Intensive computation remains unavailable in this session.

- CTR-0.2 fixture is deliberately synthetic; its three-byte state/event schemas are not production formats. Generic random streams use mt19937_64 and seed_seq; domain separation and consumption isolation tested, not statistical independence or cryptographic security.
- Bounded sampling requires uniform full-width input; untrusted/adversarial sources can stall rejection. No RNG persistence, authenticated replay, weighted chance, production hidden-information interfaces or production performance benchmark yet.
- CTR-1 game-specific work blocked by authorization/provenance; generic contracts can proceed independently.

- CTR-1 subtask A implements only an original fixed two-player/four-slot synthetic fixture. Opponent private labels are omitted, but slot IDs, ownership and counts are structurally public/inferable; no hidden ordering, visibility history, stale-action protection, arbitrary observation validation or process isolation. Observation is a trusted projection, not a sandbox. Subtask C now integrates the synthetic fixture with resource transitions and action replay; production integration remains absent.
- Rights ledger schema 1 is a manual admission gate, not machine-enforced authorization. No official sources admitted; official timing, zones, combat, scoring, resources, triggers, replacements and continuous effects remain unimplemented. CTR-1 full gate open.

- Subtask B resolver is a synthetic two-balance fixture; subtask C integrates it with subtask A through a fixed payment program, not a production rules engine. Exact-event matching only; immutable rule tables, lowest-ID replacements, ID-ordered FIFO triggers. These are fixture conventions, not official timing rules. No player ordering choices, condition predicates, continuous effects, dynamic registration or simultaneous resolution. Limits reject entire transactions, including potentially finite long chains; trigger cycles are bounded rather than semantically classified. Trace is in-memory, not canonical serialized replay; no agent exposure or production benchmark. No official rule verification.

- Subtask C uses a fixed two-player, four-slot model and an immutable synthetic payment program. The pre-action cost is 3 minus own public slots; a replacement changes debit 3 to 2, so both possible legal reveals cost 2 and trigger a credit to the opponent. This validates recomputation and ordering, not general continuous-effect semantics or a changing final cost. No dynamic modifier registration, layers, dependencies, timestamps or general effects.
- Subtask C replay reconstructs state from version-1 initial state and action bytes, with a 32-action input cap. No serialized effect trace, integrity/authentication, external rules/program digest, explicit chance in this fixture, or production replay. Serialized full state contains private labels and is authority-only. Trusted observations are not adversarially validated; subtask E narrows filtering to ResourceViolation; other invalid_argument and engine faults propagate. A future extensible program still needs context-sensitive distinction between unaffordable actions and configuration-caused resource faults. No broad secrecy or production performance guarantee.
- Official combat, scoring, rules provenance and other official CTR-1 acceptance requirements remain outstanding. No official game-specific source admitted.

- Subtask D is standalone synthetic simultaneous conflict: four fixed public slots, HP/power 1..3 or removed (0,0), immutable ownership, one target or idle per slot, kill-count scoring and a four-round cap. No official combat or scoring semantics, priority windows, player-specific order collection, hidden choices, resource costs, trigger integration, replacement effects, healing or respawn. It is not connected to subtask C. No legal-order enumeration interface or exhaustive proof over full state space. Replay is bounded, versioned and deterministic but not authenticated. Terminal outcomes are derived rather than independently stored. Official CTR-1 remains blocked.

- Subtask E evaluates bounded integer set/add/multiply operations in (layer,id) order from a four-bit activation mask, with fixed limits on base, intermediate values, layers and rule count. Activation/deactivation is by changing the supplied mask; no dependency graph, arbitrary predicates, durations, timestamp precedence, dynamic effect registry, caching or official modifier layers. Bounds violations are configuration/input errors. A separate modifier/payment fixture has variable final cost; the integrated v1 reveal still costs two. No full official rule coverage or arbitrary-program safety proof.

- CTR-E0008 adds structural observation validation for the fixed synthetic model, not authentication, freshness, truth against authority, process isolation or general secrecy. Valid-looking fabricated projections cannot be detected without authoritative comparison. Direct payment validates candidate membership; generic ResourceViolation context is still unresolved for arbitrary programs. Existing cost helper is not a standalone authenticated input API.
- Replay envelope has a fixed eight-byte fixture identity tag and checks reconstructed final state. It is an in-memory wrapper, not a serialized wire format, cryptographic digest, signature, trusted checkpoint or official rules/content manifest. A consistently altered log and final state may pass; existing raw v1 replay remains available. No production manifest or official rule admission. See docs/CTR1_GATE_AUDIT.md.

- CTR-E0009 provides a canonical Python run manifest and exact byte comparison against an independently trusted expected SHA-256 digest. It is not signed, does not establish provenance or permission, does not load or execute artifacts, and is not yet wired to native replay. Trust in the expected digest and using the exact verified bytes remain caller responsibilities. Artifact byte sizes are caller-bounded; manifest is capped at 4096 bytes. No production checkpoint, verified engine binary loading, official rule digest or game data. No native Riftbound games.

- CTR-E0010 binds the seven-role manifest to existing native synthetic replay on Linux only. The caller must independently trust the expected manifest digest, executable path and local execution environment. Fixed rules/content descriptors are compatibility markers, not loaded rules/data or official source hashes. Executable is copied into a private temporary directory after byte comparison; no hostile same-user/OS protection, signature, sandbox, shared-library/environment identity or production deployment guarantee. Worker accepts at most 189 input bytes, 32 actions; output expected 26 bytes; subprocess timeout 5 s. Captured output is not independently capped for a faulty or malicious executable. Engine artifact size capped at 32 MiB. No Windows/macOS integration validated. Manifest and replay hold private authoritative bytes, not agent input. No official Riftbound games.

- CTR-E0011 records candidate public rule-source metadata only. Indexed hub and opened cached hub disagree (October/November versus July versions); exact current CR/TR file locators and hashes unresolved. No admission or official rule-to-test inventory. Regional legality, experimental start rules and event-specific overrides must not be silently applied globally. General copyright guidance on methods vs expression is not case-specific clearance for automated gameplay, card-data processing or distribution.

- CTR-E0012 validates explicitly trusted, caller-supplied source pins/review records and exact source bytes; it cannot determine completeness of the source inventory, authentic reviewer identity, legal permission, effective precedence, actual review date or correctness of source contents. Explicit finite inclusive effective/review intervals and exact scope matches are conservative engineering choices; no wildcard expansion or automatic precedence. No official review records exist. Standalone Python utility not yet connected to native replay, a loader or CTest. Only new focused test suite executed; no full baseline source workspace available. No official source admitted or game simulated.

- E0013: private source research record requires durable user-controlled retention outside GitHub. Current official document bytes and scoped admission still unavailable. No official rule coverage. Previous public history remains unchanged; no claim of erasure.

- E0014: source-admission CTest registration now present in root CMake configuration; tested using an isolated exact-registration harness only, not a complete root project build. Full native workspace could not be retrieved (DNS failure). No change to runtime admission enforcement. Current rules artifacts and scoped review remain outstanding; no official rule behavior.

- E0015 supersedes the earlier base-reference availability blocker: supplied artifacts are readable and structurally indexed, but independent publisher byte comparison, precedence/completeness and scoped admission remain unresolved. Structural index agreement is not semantic rule coverage. Private records must remain available to the user. No new engine implementation or regression run.

- E0016: provisional work-package routing and manual fixture candidates are not complete semantic classification or executable tests. No native regression rerun.

Local clone still fails DNS; no local workspace restoration. The CI workflow is restricted to the named validation branch and public repository guard, not an automatic main-branch or cross-platform validation service. Runner toolchain image is recorded but not immutable-pinned; no executable SHA-256 values emitted in this run. No official source admission or behavioral coverage.

- E0018: generic object storage has configurable limits (64 principals, 256 containers, 4096 objects and transfers). Snapshot values are publicly mutable within authority code; apply copies and validates, not an immutable persistent database or concurrent transaction manager. Caller must assign unique session IDs and control access to snapshots, viewer selection, and transaction submission. Revision/session equality is freshness checking, not authentication. Container existence, IDs, revision and optionally counts are exposed metadata; visible object IDs may permit correlation across observations. Hidden type/order perturbation tests are not proof of total information-flow security. No ownership transfer, object creation/destruction, same-container reordering, serialization, randomization, production zone semantics, agent interface or rule integration. Object ownership does not grant action legality. Official scope/rights and rule-derived evidence remain unresolved.
